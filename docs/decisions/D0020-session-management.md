# D0020: Managing sessions: rename, stop, archive, pin, fork, delete

Date: 2026-11-15. Status: active.

## Context
The owner asked for session management in intuition itself (T-0029): the everyday operations on sessions in the runner, the chat view and, where it fits, the dock. Sessions are also Claude Code transcripts, shared with the terminal through the sync (D0015, D0016), so each operation has to say what it does to the transcript.

## Decision
- **One POST route per operation**, `POST /api/sessions/:id/<rename|archive|pin|stop|fork|delete>`, each with a JSON body (`{}` when there is nothing to say), so every one passes `refusal()` like the other writes, content type included. Delete is a POST too, not a DELETE: the same guard, no exception for a body-less method.
- **What touches the transcript.** Rename sets the runner's title and the transcript's custom title (`renameSession`), so `claude --resume` shows the same name; a transcript that can't be renamed is logged and the runner's title stands. Fork uses `forkSession` (a new transcript, a new Claude Code id) rather than `resume` with `forkSession: true` on the next turn, so the fork exists, with its own id and title, before anyone replies to it, and doesn't depend on the source still being there. Delete uses `deleteSession`. Archive and pin are the runner's alone (`SessionMeta.archived`, `pinned`; absent when off) and never touch the transcript.
- **A session from the terminal is never deleted here** (409 `TERMINAL_NOT_DELETED`); the pages don't offer Delete for one. It may be archived, renamed, pinned and forked. Delete is also refused while a turn runs (here or in a terminal), and a transcript that won't go and is still there keeps the session as it was (500); one that is already gone doesn't stop the delete.
- **The sync is told.** A rename is the runner's own write (`Sync.own`), so it neither shows the session running nor makes the next reply a 409 "open in a terminal". While a fork is written the sync imports nothing new in that workspace (`hold`), then adopts the fork with its cursor at the end (`adopt`). A deleted session's Claude Code ids stay linked to the gone id (`forget`), so a transcript left behind is never imported back.
- **Stop is the SDK's interrupt.** `Query.interrupt()` ends the turn as Esc does in Claude Code; if it hasn't ended five seconds later, the query is aborted. Open approvals are answered "deny" first. Whatever the driver says after the stop is not stored: the turn ends with a `stopped` event and the session `idle`, with no notification (the person did it). The route waits (up to ten seconds) and answers with the session. Smoke-checked against real Claude Code (`scripts/smoke-manage.ts`): interrupt works on our string-prompt queries.
- **A turn that is over but still closing counts as over.** The SDK's query shuts Claude Code down after the result, so the runner still holds the turn for a moment while the session is already `idle`. A reply already accepted that; now fork and delete do too (they wait for the close, at most five seconds, before touching the transcript), and the reply's "open in a terminal" check no longer counts the runner's own closing turn as another process's write (it did, so a reply sent the moment a turn finished could be refused).
- **Lists.** `GET /api/sessions` leaves archived sessions out and `?archived=1` lists only them; pinned first, then newest first. The WebSocket's `hello` still carries every session with its flags, and a new `removed` message says a session was deleted; the pages filter for themselves. The dock leaves archived sessions out of its pill, peeks and list.
- **The pages** share `chat-manage.js`: the list's rules (pinned first, the Archived view, search over title and workspace by every word, the workspace filter), what the menu offers, the delete confirmation's words, the routes, the menu and the inline rename. The chat view has a search box, a workspace filter and an Archived toggle above the list; a "…" button (in place of the row's time, on hover or focus) and right-click open the menu. F2 renames and the Delete key archives the focused row (else the session shown), when no text field has the focus; archiving says so on a line under the list with Undo for six seconds. Delete asks in a modal `<dialog>` that names the session and says its Claude Code transcript goes, for good, with the focus on Cancel. The dock has Stop in its head and a right-click menu on rows with Rename, Pin and Archive only; the menu and a rename hold the dock open as a focused reply does.

## Why
- One route per operation keeps each body small and each refusal specific, and keeps the guard uniform.
- Deleting a terminal session's transcript from here would remove something the person made elsewhere; archiving hides it from intuition without touching it.
- `forkSession` gives the fork a transcript at once, which `claude --resume` lists and which survives the source's deletion.

## Risk
- A session the runner restarted in a new conversation after a failure (no Claude Code id at the time) may have had other transcripts; delete removes only the current one.
- A rename while Claude Code writes the same transcript appends the title entry between its lines, as `/rename` does in the terminal.
