# D0046: A hotkey for the chat in the notch, every key written once and shown where people look, and tooltips the pages draw

Date: 2026-11-24. Status: active. No foreman task (asked for in a session by the owner). Adds a third global hotkey to the two of [D0021](D0021-shell-settings-from-the-runner.md) and [D0040](D0040-dock-switch-and-command-keys.md), a way into the chat of [D0042](D0042-chat-in-the-notch.md), and changes the pop-up's key for removing the clipboard.

## Context
The owner, on 2026-11-24: "is there a hotkey to go from notch to chat? make sure there is a clear guide for hotkeys, add tooltips on hover". There was none: the chat was a click on the notch, the tray's Open chat, or a link. The pages' keys (D0036, D0040) were written in four places (the pop-up's and the snip's hint lines, a few `title`s, the decisions) and nowhere in one list a person could open. Many icon buttons in the dock and the chat had no tooltip, and native tooltips may not show at all for the dock, a non-activating panel of an app that is not the active one.

## Decision
- **A third global hotkey, `chatHotkey`: ⌘⇧J on a Mac, Ctrl+Alt+J on Windows and Linux.** Pressed with the dock on, the shell sends the page `holm-dock:chat-key` (the preload's `onChatKey`, which hands the page nothing); the page grows into the chat on the session it would open on, or, showing the chat, closes it to the pill. The page decides, since it knows its state. Grown, the page reports `chat`, and the shell gives the window the keyboard as for a click. With the dock off (or its page not loaded) the chat window opens as the tray's Open chat does, and closes when pressed while that window has the keyboard. Like the other two it does nothing while Settings has the keyboard.
- **It is a setting like the other two.** `ShellSettings.chatHotkey` is optional in the contract: settings written before it have none, and the shell (`parseShellPrefs`, `migratedPrefs`), setup and the pages use the default; Settings stores it at its next save. Its own row in Settings' Shortcuts, recorded the same way. No two hotkeys on the same keys: the Settings page says so under the row at once and sends nothing, and the runner refuses such a PUT with 400 at the later field ("This is already the Snip shortcut."). The shell's report has `hotkeys.chatHotkey`, and the Setup line counts three. Setup asks for it with the other two (`--chat-hotkey`, optional for scripts).
- **Every key is written once, in `src/web/shortcuts.js`.** The three global keys (as recorded, else the defaults, which a test holds equal to `shell/src/os.ts`) and the pages' keys by section (Dock, Chat, New task and snip), each a list of combos in neutral words (`cmd`, `alt`, `shift`, `ctrl`) drawn in the platform's (⌘ ⌥ ⇧ ⌃ on a Mac, Ctrl Alt Shift elsewhere). From it come: the guide; the pop-up's and the snip's hint lines (`HINTS`, drawn at load); and every tooltip that names a key (`tip("Switch session", "dock.switch")` is "Switch session (⌘K)").
- **The guide is a sheet** (`shortcuts-sheet.js`): ? (when the keyboard is not in a text box), "Keyboard shortcuts" at the end of the dock's "…" (there even with no session), or the ? button in the chat's sidebar head. In the dock it is the whole panel, in the island's colour, the panel held at the open dock's height while it shows, and it holds the dock open; in the chat it floats near the top in the frosted glass, two columns where there is room. Esc closes it and nothing else (it takes Esc before the switch, the dock or the chat do). It is drawn again when the settings change, so a newly recorded key shows. Settings shows the same rows, read-only, under its recordable ones.
- **The guide is held to the code.** `test/web/shortcuts.test.ts` sends every press of letters, digits, arrows, Tab, Enter, Esc, Backspace and ? with every set of modifiers through `dockKey`, `commandK`, `workspaceDigit`, `isAgentKey`, `isRemoveKey` and `isGuideKey`: each press a handler takes is in the guide, and each the guide names is taken, on a Mac and off one. The keys only a page's source handles (F2, Delete, Esc, Enter, Tab) are checked by their source. Every id a page names in a tooltip is in the list.
- **Tooltips are the pages' own**, on every page (`tooltips()`): a control's `title` becomes its tooltip, drawn after half a second's rest of the pointer or at once on a keyboard focus, under the control (over it with no room) and kept inside the element it belongs to (the island's panel in the dock, so the shell, which takes the mouse only on the island, never has a tooltip outside it), in `--ink` with the tokens, a fade that reduced motion turns off. A control named only by its title keeps the name as `aria-label`. Glyph-only and terse controls got one: the dock's switch (its whole title, then "Switch session (⌘K)"), "…", New task (with its global key), the expand button ("Open in the chat (⌘⇧J)"); the chat's New task, ?, back to the dock ("Back to the dock (Esc). Close the chat (⌘⇧J)"), the search, Archived, Stop and the rows' "…"; the pop-up's and the snip's agent switch (with ⌥A) and the clipboard's ×; Settings' ↑ and ↓. The harnesses check that every visible button and link has a name, and every glyph-only one a tooltip.
- **⌘K finds a session in the chat window too**, not only in the notch: the guide lists one Chat section.
- **The clipboard attachment goes with Backspace in an empty task**, pressed, not held, as a recipient's chip goes from a mail's To field. Alt+Backspace is no longer taken: on a Mac Option+Backspace deletes a word in every text box, and the pop-up had swallowed it.

## Why
- **J.** ⌘⇧J and Ctrl+Alt+J are no system shortcut on macOS, Windows or GNOME and KDE; they type nothing (⌘ never types, and AltGr+J is no character on the common European layouts: German, French, Nordic, Polish, Czech among them). J is under the right index finger beside K, the pages' own ⌘K. What it takes from apps while the hotkey holds it: Chrome's and Mail's ⌘⇧J on a Mac (Downloads, Mark as Junk), both rarely pressed. The others weighed took more: ⌘⇧C and ⌘⇧I (browser inspectors, many editors), ⌘⇧E and ⌘⇧O (editors' explorers and file pickers), ⌘⇧. (Finder's hidden files), ⌘⇧Return (terminals' zoom), ⌥⌘Space (Finder's search window). It can be changed in Settings like the others.
- **The page decides the toggle**, not the shell from its last reported state: the page knows whether it is in the chat, stepping down, or closing, and a state report in flight would make the shell's guess wrong.
- **One list in a module**, not the guide's HTML: the pages that need a key (the dock, the chat, the pop-up, the snip, Settings) already load modules, and a list that tests can read is one the code can be held to.
- **The pages' own tooltips** over `title`: inside the black notch an OS tooltip may not show (the dock is a non-activating panel of an inactive app on a Mac), and where it does, it is a light box half outside the island, where the shell lets the mouse through. One component on every page keeps them alike.
- **Backspace in an empty task** over moving the key to another modifier: every Backspace with a modifier edits text on some OS (Option and Ctrl delete a word, ⌘ to the line's start), and an empty task box has nothing for Backspace to delete.

## Alternatives
- A hotkey that only opens the chat, with Esc to close it: the owner asked for one key to go there; the same key back is what the snip's and New task's toggles taught.
- A Settings-only list of keys: nobody opens Settings to find out what ⌘K does in the dock.
- `title` and nothing else: see Why.
- A modal `<dialog>` for the sheet: in the dock its backdrop would cover the whole transparent window, outside the island.

## Risk
- A global ⌘⇧J takes Chrome's Downloads key and Mail's Mark as Junk while the shell runs. Settings changes it.
- ? opens the guide only away from text boxes; in the dock the keyboard is usually in the reply box, so there the "…" is the way.
- An older dock page (a runner older than the shell) ignores the chat's hotkey; an older shell sends a report without `chatHotkey`, which the runner still takes.
