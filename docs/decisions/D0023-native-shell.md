# D0023: The shell on macOS and Linux: one OS module, launch agent and autostart files for login, X11 when there is a DISPLAY, an opaque dock without a compositor, and a temp-folder rule for image paths

Date: 2026-11-15. Status: active. Task: T-0032. Builds on [D0019](D0019-platform-layouts.md) (the command line's side).

## Context
The owner on 2026-11-15: intuition must set up on macOS and Linux as well. D0019 gave the command line three layouts and a `runner: { kind: "local" }` entry in the native shells' settings. The shell's own code (`shell/src`) still assumed Windows: wsl.exe to start the runner, Control hotkeys, a dock on the display's very top edge, Electron's login item, and Windows image paths that the runner turned into `/mnt/c` paths.

## Decision
- **One pure module, `shell/src/os.ts`.** What differs per OS is answered there, without Electron imports, so it is unit tested on any machine: the default hotkeys (Command+Shift+Space and Command+Shift+S on a Mac, Control+Alt elsewhere), the runner's start command, the dock's area, whether the dock can be transparent, the Linux notices and the Screen Recording check. `main.ts` asks it and keeps the Electron calls. The OS comes from `process.platform`; `INTUITION_PLATFORM` is the command line's and is not read by the shell.
- **The local runner starts as a detached child.** `runner: { kind, repo, bun }` (read with the same `parseLocalRunner` the command line writes with) gives `bun <repo>/src/cli.ts start --login-env`, spawned with an argument array, no shell, detached and unref'd. `--login-env` as on Windows: a shell started at login lacks the person's PATH.
- **Start on login is a file the shell writes, on both native OSes.** Linux: the XDG autostart entry the command line already writes (one `autostartEntry`, now in `shell/src/login.ts`, used by both). macOS: a launch agent, `~/Library/LaunchAgents/dev.intuition.shell.plist`, that runs the installed Electron on the app folder, instead of `app.setLoginItemSettings` as the task's spec said. Electron's login item on a Mac registers the app bundle, which here is npm's `Electron.app`: at login it would start Electron's default app without the shell's folder. The tray's checkbox, `--login on|off|status` and `intuition shell login` all use the file. Windows keeps Electron's login item.
- **X11 whenever there is a DISPLAY.** On Linux the shell appends `--ozone-platform=x11` before ready when `DISPLAY` is set (XWayland on a Wayland desktop). Global shortcuts, window placement and always-on-top work there; on Wayland an app may not place its windows or grab keys. Without DISPLAY the shell runs on Wayland and says once that the hotkeys may not register and the tray does the same.
- **The dock is opaque when a transparent window would be black.** Transparent on Windows, macOS, under Wayland (XWayland included) and on X11 desktops that composite by default (GNOME, KDE, Xfce and others named in `os.ts`). Otherwise (a bare window manager, Xvfb) the dock's window is the island of the state the page last reported, at the top centre of where the transparent window would be, and follows the state. `INTUITION_DOCK_OPAQUE=1|0` overrides the guess. A transparent dock is still never resized for a state (D0010).
- **A Mac's dock hangs from the work area's top** (on a display with a notch, it grows out of the notch instead: [D0035](D0035-dock-from-the-notch.md)). The display's bounds for x and width, so it is centred on the display; the work area's top for y, so it sits under the menu bar and, on a display with a notch, under the notch.
- **Screen Recording is detected, said once, and opens its pane on click.** `systemPreferences.getMediaAccessStatus("screen")` at start and before a snip; a notification whose click opens `x-apple.systempreferences:com.apple.preference.security?Privacy_ScreenCapture`. The snip still opens. The settings page's line for it is the later Setup task.
- **The runner's image rule follows the layout.** `windows-wsl` keeps `/mnt/<drive>/`. On macOS and Linux the runner takes only a PNG directly in `<os.tmpdir()>/intuition/`, compared by real path (the folder's own links included: `/var` is `/private/var` on a Mac), and stores the real path. The shell saves into `app.getPath("temp")/intuition`, the same folder.
- **The self-test judges each layout, and names what it cannot judge.** `selftest-run.ts` installs and runs the shell for the detected layout. Paths are judged per layout; the dock against `dockArea` and, when opaque, against the island. Two known empty captures are skipped and printed, not failed: macOS without Screen Recording (only a person can grant it, so CI cannot), and WSLg, which gives Electron no pixels. An overlay a pixel short is taken on Linux: WSLg's window manager keeps windows a pixel smaller than the display.

## Why
- Pure functions for every OS difference mean the macOS and Linux branches are tested on this machine and in the plain CI job, where neither OS's Electron runs.
- A launch agent is plain launchd, needs no signed helper or bundle change, and starts exactly what `shell start` starts.

## Risk
- Nothing here has been seen on a Mac by a person. The macOS CI job runs the self-test on GitHub's runner, which has a logged-in desktop but no Screen Recording.
- A launch agent written while the shell runs takes effect at the next login. macOS 13 and later show "Background Items Added" for it.
- The compositing guess on X11 is by desktop name. A desktop that composites but is not named gets the opaque dock; the variable fixes it.
